# 通用灯具支持（1.0.1）

本版本以 HA 的 `light` 实体为接入依据，不再要求所属设备名称包含“灯”或“light”。支持墙壁开关上的灯路、晾衣机照明、模板灯、灯组和没有设备条目的灯实体。

同一 HA 设备下的多个灯实体分别桥接，拥有独立 SN，分别接收控制和上报状态。原设备的首个灯路继续使用基于 device_id 的旧 SN；新增灯路使用实体注册表 ID 生成确定性 SN。首个灯路的选择保存在集成配置条目的 `primary_lights` 中，实体重新排序或重命名不会切换已经分配的灯路。没有 unique_id、也没有实体注册记录的 YAML 灯使用 entity_id 作为身份，重命名会改变其 SN。

开关灯只映射开关服务；调光灯增加亮度服务；支持色温的灯增加色温服务。色温控制会按照灯具实际公布的 Kelvin 范围裁剪，例如 2700–5700 K。亮度按产品适配器比例转换，支持下发 0。实体关闭时，亮度或色温为 null 不影响能力识别。

灯具新增、重命名、启用或禁用后，会延迟约 2 秒重新发现。新灯状态同步会延迟约 30 秒，避开 HiLink SDK 的批量绑定阶段。HA 禁用的源实体、禁用的源设备以及反向华为集成的实体会跳过；桥接管理中已排除的设备不会因状态变化自动恢复。

原生 SDK 按内容哈希复制到 `.storage/hwhomebridge/lib/` 再加载，避免 HACS 更新时覆盖进程正在映射的 `.so` 文件。首次从旧版升级仍应停止 HA 后替换文件再启动；此后 HACS 下载不会覆盖运行中的 SDK 缓存。

当前华为 PID 的 profile 仍是原项目定义，提供开关、亮度、色温。RGB 灯可接入并使用开关和亮度，但本次没有新增华为 RGB profile，也没有实现华为端选色、效果或渐变。固定 profile 的 App 面板可能仍显示灯具不支持的滑块，这类命令不会发给 HA。

## 排查记录

现场通过 HA 2026.9.4 页面核对到 19 个 light 实体，原集成页面显示 13 个设备。典型缺失原因：

- Aqara 妙控开关 S1E、米家智能晾衣机、主卧开关、主卧卫生间的设备名称不满足原名称关键词要求。
- 入户开关有两个独立灯实体，原聚合方式只选取一个灯实体。
- 19 个 light 实体中包含路由器指示灯；不需要桥接时可在集成的设备管理中取消选择。

这说明源码中的发现和聚合限制能解释当前漏接情况；C SDK 为预编译闭源库，最终绑定和控制效果仍需安装后验证。

## 升级与回滚

1. 备份 HA 的 `custom_components/hwhomebridge/` 和 `.storage/hwhomebridge/`，保留原网关和设备绑定。
2. 将本仓库 `custom_components/hwhomebridge/` 的完整内容覆盖到 HA 对应目录；包括新增的 `light_support.py` 和本仓库已有的 `native_async.py`。
3. 重启 HA，在集成页核对版本 1.0.1；日志应出现 `Light discovery: 19 entities, 19 mapped, unmapped=[]`（实体数量以实际为准）。
4. 等待华为智慧生活完成绑定和状态同步，分别检查两路入户射灯、客厅射灯、晾衣架灯、衣柜灯和主卫灯。
5. 回滚时停止 HA，恢复备份的集成目录和桥接存储目录，再启动 HA。不要通过删除集成来升级，删除操作会清除华为侧网关绑定。
